# OneShowSEO 内容运营重设计 · 2026-09-08

## 产品方向

服务需要持续生产和发布内容的企业与运营团队。围绕项目开展“明确需求 → 内容计划 → 创作与审核 → 内容资产 → 渠道发布 → 结果复盘”。保留四个独立内容菜单，菜单与页面流程入口使用同一导航。

本次交付是内容运营主流程重设计。没有把 MoGrow 的展示图当成已经实现的技术能力，也没有宣称完成全平台自动发布或完整流量归因。

## 已实现

- 首页改为内容增长工作台，提供状态计数、筛选、标题/关键词搜索、具体文章的下一步、模型与发布连接准备情况。
- 内容菜单移到工作台下方；研究工具归入“发现机会”，结果入口归入“效果与监控”。原站点概览保留在“网站概况”。
- 创建内容直接打开计划表单。首屏仅显示主题、核心关键词、读者、内容目标；结构、字数和平台方向折叠展开。
- 保存计划立即显示该计划，继续确认生成；生成成功进入对应文章编辑器。任务编号会解析为文章编号。
- 审核通过后进入该文章的发布记录；可清除文章筛选。支持选择已授权的 WordPress 目标站点，同一版本在不同连接下分别判断是否已创建发布任务。
- 发布页面减少重复标题、无效批量按钮和无数据的图表；保留审批、定时发布、正文预览、重试、日历与记录。
- 新增内容表现入口，展示真实发布任务、外部链接、核验状态。流量与转化未接入时明确显示，不伪造零值。
- 内容状态按最新正文版本判断；旧版本上线不会把新草稿标为已发布；另一渠道失败或核验失败仍可处理。已归档文章不进入首页待办。
- 页面采用后台真实任务状态，避免内容生成后存储失败/任务隔离仍显示可编辑。没有可用版本或任务未结束时不允许提交审核。
- 修复重试时已完成用量记录与再次提交 pending 状态冲突的问题；校验用量请求仍由原计费服务执行，重试不产生第二条记录。

## 自测

- 独立本地测试库、账号和文件存储，与正式项目隔离。
- 浏览器实测：创建计划、默认高级选项、保存并打开计划、确认生成、任务排队、编辑器定位、生成产物、编辑保存 V2、提交审核、管理员审核通过、进入文章对应的发布管理。
- 实测了桌面与 390px 手机宽度的工作台和发布页，检查侧边导航、流程入口及状态筛选。
- 浏览器实测发布连接缺失的提示；没有在正式站点发布测试文章。
- 回归测试覆盖：旧版本发布、新版审核、多渠道失败、页面核验失败、任务编号映射、未知链接协议、后台重试及用量只记录一次。
- 完整测试 380 项通过。lint 无错误（保留原有两条警告）。全仓库 TypeScript 检查仍有既有错误；本次新增模块与修改的内容组件未出现类型错误。

## 上线后的建议测试顺序

1. 打开工作台，确认四个内容菜单在上方可直达。
2. 点击“创建内容”，输入主题与关键词，保存计划。
3. 确认模型及费用，开始创作；正文出现后修改并保存。
4. 核验事实，提交审核，再审核通过。
5. 前往发布管理，选择自己的已连接站点，预览并提交发布审批。
6. 确认目标和正文后批准发布；在内容表现中检查发布链接及核验状态。

## 当前边界与下一阶段

真实自动发布仍以 WordPress 为主。其他平台方向可用于计划，尚未实现自动分发。GA4 / Search Console 自动同步及逐篇转化归因尚未接通；已有数据分析不能据此承诺获客效果。下一阶段应优先完成品牌资料在生成中的复用、渠道版本适配和一个真实可验证的数据回流接入，再扩展新平台。
